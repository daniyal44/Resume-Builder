ATS resume guide: how to pass applicant tracking systems in 2026

Most mid-sized and large employers screen applications with software before a recruiter reads a word. This guide explains how that software actually reads your resume — and the concrete formatting and keyword changes that keep qualified candidates from disappearing.

What an applicant tracking system actually does

An applicant tracking system is a database with a parser attached. When you upload a file, the parser converts it into plain text and then tries to map that text into fields: name, email, phone, employers, job titles, dates, education, skills. Those fields are stored as a searchable candidate record.

Recruiters then search that database the way you search a website — by typing queries like “product manager SQL fintech”. Your resume appears if the parsed record contains matching terms. A layout that destroys the text layer, or a resume that never mentions the query words, simply never surfaces.

The important consequence You are not writing for a robot that judges you. You are writing so that a human's keyword search can find you and so that the record it finds is accurate.

Why strong resumes score low

In practice, resumes fail for five predictable reasons:

  • No text layer. Scanned PDFs, exported images and some design-tool exports contain pixels, not words. The parser gets nothing.
  • Layout order is scrambled. Multi-column resumes can be read across the page, so a job title ends up attached to the wrong company or date.
  • Headings are unrecognisable. “Where I've been” instead of “Experience” forces guesswork; parsers rely on conventional labels.
  • Contact details live in a header, footer or image. Many parsers ignore those regions entirely, so the record has no email address.
  • Different vocabulary from the job ad. If they search “stakeholder management” and you wrote “worked with clients”, no match is found, however true it is.

Formatting rules that survive parsing

Element Safe choice Avoid
File typeText-based PDF (or DOCX if requested)Scanned PDF, JPG, PNG
ColumnsOne column, top to bottomThree or more columns, text boxes
Section headingsExperience, Education, Skills, ProjectsClever or invented headings
DatesJan 2022 – Mar 2024 (same format everywhere)“2022–now”, seasons, mixed formats
Contact blockTop of page one, in the bodyHeader/footer area, image text
BulletsStandard round bulletsCustom icon fonts, tables as bullets
FontsOne or two common families, 10–12pt bodyDecorative or symbol fonts
Photos & graphicsOmit unless the market expects oneSkill bars, charts, logos as content

If you want the safest possible option, choose a single-column template such as Classic or Minimal. They keep reading order unambiguous while still looking professional.

Keyword strategy that reads naturally

Keywords are not a trick; they are the vocabulary of the role. A practical method:

  1. Save the job description and highlight every noun phrase that describes a skill, tool or responsibility.
  2. Count repeats. The phrases appearing most are the ones the recruiter will search.
  3. Separate must-haves from nice-to-haves. Only claim what you can defend in an interview.
  4. Use the employer's exact term once, then your natural phrasing — “stakeholder management (regular reporting to commercial and product leads)”.
  5. Mirror the job title in your headline when it is accurate: “Product Manager — B2B SaaS”.
  6. Keep a plain-text skills section of 10–20 genuinely held tools and methods.
Weak bullet Worked on the mobile app and helped the team with releases.
ATS-friendly bullet Led release process for a React Native app used by 40k monthly users; cut crash rate 28% and shipped 12 releases per year across 4 squads.

The second version contains the role vocabulary (release process, React Native, crash rate), a measurable outcome, and no keyword stuffing. That is the pattern to copy. For structure and length rules, read the resume format guide.

Pre-submission checklist

  • File opens as text — try selecting your name with the cursor in a PDF viewer.
  • Contact details appear as normal body text on page one.
  • Section headings use conventional names and consistent date formats.
  • Job title, company, location and dates are on separate, readable lines.
  • The 10 most important job-ad phrases appear somewhere truthful.
  • No text lives inside images, charts, tables or text boxes.
  • One page for under ten years of experience; two pages maximum otherwise.
  • File name is human: Firstname-Lastname-Resume.pdf.
  • Proofread once on screen and once printed — spelling errors survive parsing too.

Frequently asked questions

What is an ATS resume?

A resume written and formatted so applicant tracking software can read it: real selectable text, standard section headings, a single reading order and the job description's keywords used truthfully.

Do resumes really get rejected by ATS software?

Mostly no — systems parse and rank rather than auto-reject. Resumes fail because the parser cannot read the layout or finds none of the job's keywords, so the record ranks low in recruiter searches.

Does a two-column resume fail ATS?

Not automatically, but it raises risk of scrambled reading order. Single-column layouts are safest; if you use two columns, keep contact details and headings in the main column.

How many keywords should a resume have?

Match the 10–20 most important requirements using the employer's wording, placed where they are truthful. Stuffing exact-match phrases hurts readability and credibility.

Should I send a PDF or a Word document?

A text-based PDF is widely accepted and keeps your layout. Use DOCX only when the posting asks for it, and never submit a scanned, image-only PDF.
